# q

A personal coding agent. `server/` is the agent (Effect v4 on Bun; see
`server/CLAUDE.md`). This crate is the terminal client: a thin, fast Rust TUI that
renders a session's stream and sends commands.

```sh
cd server && bun run dev        # the server on :7777 (needs ANTHROPIC_API_KEY in server/.env)
cargo run                       # a new conversation (-- -c continues the latest, -- -r picks one)
cargo test                      # unit + golden tests
cargo clippy --all-targets      # pedantic, must be clean
```

Without a key: `bun run fake-anthropic` in `server/`, then start the server with
`Q_ANTHROPIC_URL=http://127.0.0.1:7778 ANTHROPIC_API_KEY=fake`. The end-to-end test
(`cargo test --test e2e -- --ignored`) runs against such a server; its header has the
exact commands.

## Layout

```
src/tea.rs         the Elm runtime: Model (init/update/view/on_event), Cmd (Task, Subscribe, Batch)
src/app.rs         the App model: sessions (new, continue, pick), messages, update, view
src/picker.rs      the session picker (its own state, transitions and view)
src/view.rs        rendering: turns to lines (Markdown via tui-markdown), the status line
src/transcript.rs  the session stream folded into turns (a port of the AI SDK's processUIMessageStream)
src/api.rs         ApiClient: commands over HTTP, and following a session stream (Durable Streams, SSE)
src/sse.rs         the SSE reader
src/wire.rs        the server's types, generated by build.rs from server/generated/wire.schema.json
tests/e2e.rs       against a running server (ignored by default)
```

## Conventions

- **No async.** Background work is a `Cmd` on a thread (`Cmd::task` for one result,
  `Cmd::subscribe` for many); results come back as messages. A subscription lasts as
  long as the model holds its `Subscription` handle: replace it to stop it. `update` never does I/O;
  `view` may only update render caches.
- **The stream is the truth.** What the conversation shows comes from folding the
  session's stream; `update` keeps only UI state of its own (input, scroll, notices).
  A new conversation has no session until its first message creates one.
  Commands (send, cancel) do not change the transcript; their effects arrive in the stream.
- **Never hand-write a type the server defines.** `wire.rs` is generated; change the
  server's schema and `bun run codegen`. Unknown chunk types from a newer server
  decode to `IncomingChunk::Unknown` and are skipped.
- **The fold must match the AI SDK.** `transcript.rs` serializes each reply as the AI
  SDK's `UIMessage` JSON and is tested against `server/test/fixtures/sessions`. When
  handling a new kind of chunk, port it from the pinned `ai` source, add a fixture
  there, and `bun run fixtures` in `server/`.
- `cargo fmt`, and clippy pedantic clean (`#[expect(..., reason = "...")]` where a lint
  is wrong for a case).
- Test `update` directly (it is pure), and views through ratatui's `TestBackend`.
